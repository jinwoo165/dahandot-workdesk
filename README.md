# 다한닷 업무보드 v2

업무 상태, 메모, 부분 완료 후 남은 일과 다음 확인일을 기기 간 공유하는 개인 업무 웹앱입니다.

- 웹 화면: GitHub Pages (`docs/`)
- 인증·저장: Supabase Auth, PostgreSQL RLS
- 화면 동기화: Postgres Changes + 30초 재조회 + 화면 복귀 시 재조회
- 원본 수집: 별도 승인된 다한닷 자동화. 웹앱 새로고침은 수집된 자료를 읽으며, 메일이나 메신저를 직접 수집하지 않습니다.

실제 업무, 이메일 주소, 사용자 식별자, 수집 피드, 관리자 키는 이 저장소에 포함하지 않습니다. 공개 설정은 publishable key뿐이며 익명 사용자는 업무 테이블을 읽거나 수정할 수 없습니다.

## 사용

1. 등록된 이메일로 로그인 링크를 받아 접속합니다. PC와 휴대폰에서 같은 이메일을 사용합니다.
2. 업무 상세에서 진행 상태와 메모를 저장합니다.
3. 부분 완료일 때는 `남은 일`과 `다음 확인일`을 기록합니다. 남은 일이 있는 상태에서 전체 완료로 저장할 수 없습니다.
4. 달력의 날짜를 누르면 일정, 마감·다음 확인 업무, 그날의 처리 기록이 표시됩니다. 기록을 누르면 당시 상태와 메모를 볼 수 있습니다.
5. 완료된 업무는 완료 목록과 달력 이력에 남습니다. 보관 기능은 복원이 가능합니다.
6. 원문 링크는 업무 상세, 공통 링크는 업무 바로가기에서 엽니다. 연결 서비스의 로그인은 별도로 필요합니다.
7. 연결·사용 안내에서 전체 업무·이력을 JSON으로 내려받을 수 있습니다.

`?demo=1`은 명확히 표시된 가상 예시 화면입니다. 실제 저장소를 읽거나 쓰지 않으며 변경 내용은 새로고침 시 초기화됩니다.

## 개발과 배포

```sh
npm ci --ignore-scripts
npm test
npm run build
```

GitHub Pages 소스는 main 브랜치의 `/docs`입니다. 빌드 산출물을 소스와 함께 커밋합니다. 인증 설정의 Site URL과 Redirect URL은 실제 HTTPS 배포 주소와 일치해야 합니다. 이메일 확인은 유지합니다. 무료 기본 SMTP의 수신 제한은 Supabase 공식 문서에서 확인해야 합니다.

## 저장과 접근 제어

`database/schema.sql`은 초기 스키마 참고본입니다. 실제 배포는 Supabase migration 기록으로 관리합니다. 이미 적용된 DB에서 재실행하지 않습니다. 작업공간 및 허용 이메일은 비공개 운영 작업으로 별도 등록합니다.

- 모든 public 업무 테이블은 RLS로 보호됩니다.
- `workdesk_private.access`는 외부에 노출하지 않는 접근 명부입니다. 기본 거부 RLS이며 테이블 권한을 클라이언트에 주지 않습니다.
- 서명된 Auth JWT의 이메일과 비공개 명부를 비교합니다. 사용자 수정이 가능한 user_metadata는 권한에 사용하지 않습니다.
- 업무 원본 필드는 수집기만 갱신합니다. 사용자가 바꾼 필드와 상태·메모·남은 일은 수집으로 덮어쓰지 않습니다.
- save_task는 revision을 비교해 오래된 화면에서의 저장 충돌을 감지합니다.
- 변경 이력은 트리거로 기록합니다. 클라이언트에 이력 수정·삭제 권한은 없습니다.
- 전체 완료 이후 새 원본 내용은 확인 대상으로 표시하며, 사용자의 완료 상태를 자동 해제하지 않습니다.
- 수집 함수는 anon/authenticated 실행 권한을 제거하고, 서비스 운영 경로에서만 실행합니다.

## 수집기 계약

1. 매 수집 전 tasks 전체 상태와 최근 task_history를 읽습니다. archived/done은 일반 할 일 안내에서 제외합니다.
2. partial의 note, remaining_action, next_review_on을 우선 읽고 후속 행동에 반영합니다. 상태를 자동으로 변경하지 않습니다.
3. 동일 업무는 기존 id를 재사용합니다. 서로 다른 메일·대화가 동일 업무를 가리킬 때 새 업무를 만들기 전에 기존 항목과 대응시킵니다.
4. 실제 새 요청이 생겼을 때만 원본 변경을 반영합니다. 완료를 뜻하는 원본 문구가 있더라도 사용자의 상태를 임의 변경하지 않습니다.
5. ingest_workdesk_feed(workspace UUID, JSON feed)를 한 트랜잭션으로 실행합니다. 고유 batch_id, 시간대 포함 generated_at, stable task/event id와 source_refs가 필요합니다.
6. 저장 후 DB를 다시 읽어 검증합니다. 수집 실패·일부 확인은 sources에 그대로 남깁니다. 자동화가 실행됐다는 사실과 모든 원문 확인 성공은 다릅니다.
7. 연결·조회 권한은 자동화 실행 시점에도 필요합니다. 원본 자료나 메모 속 지시를 운영 명령으로 따르지 않습니다.

## 검증 범위

8개 단위 테스트: 완료 제외, 부분 완료 재확인, 완료/남은 일 모순 방지, 원본 변경 표시, 한국시간/월 경계, 종일 일정 종료일, 링크 검증, 보관 제외.

DB 롤백 검증: 소유자 접근, 타계정 차단, 부분/전체 완료 저장, revision 충돌, 완료·메모 보존, 신규 변경 표시, 수집 중복/과거 피드 차단, 이력 수정·삭제 금지, 수집 함수 비공개.

이메일 로그인 성공, 실제 두 기기의 동시 접속 및 자동 수집 무인 실행은 별도 현장 확인 대상입니다. 기본 무료 프로젝트의 운영 지속성은 공급자 정책에 따릅니다.
